# Kikoeta-LLS

<img src="public/logo.png" alt="Kikoeta-LLS Logo" width="128">

Kikoeta 的独立远程歌词库。把歌词集中存放在电脑或服务器上，通过网页管理，再由 Kikoeta 连接并导入；也可以接收 Kikoeta Transl 生成的歌词。

## 功能

- **网页管理**：按作品号前缀或文件路径搜索，查看歌词文件、修改 AI 标记、删除文件。
- **歌词导入**：支持 LRC、TXT、SRT、VTT、ASS、SSA，可一次上传多个文件。
- **ZIP 批量导入**：识别 RJ / VJ / BJ 作品号，支持内嵌 ZIP，可选择跳过或覆盖同名歌词。
- **Kikoeta 接入**：提供兼容的远程歌词库接口，供客户端浏览和导入。
- **Transl 同步**：使用独立账号密码或密钥，接收翻译任务的歌词产物。
- **使用偏好**：支持浅色／深色主题、默认 AI 标记和 ZIP 同名文件处理设置。

## 快速开始

### Windows

可选择安装版或便携版：

- **安装版**：运行 `kikoeta-lls-<版本>-windows-x64-setup.exe`，按向导选择 C 盘以外的安装目录。安装程序会创建开始菜单快捷方式，也可选择桌面快捷方式。
- **便携版**：把 `Kikoeta-LLS.exe` 放入有写入权限的文件夹，双击运行，无需安装。

两种方式都无需另装 Node.js。启动后程序只显示托盘图标，不打开自己的窗口；服务就绪时会自动用默认浏览器打开管理页。右键菜单只有「端口：2376」「重启」「退出」，点击「端口」可再次打开管理页。首次使用以 `admin / kikoeta-lrc` 登录，并按提示设置至少 6 位的新密码。

歌词与账号始终保存在 **EXE 同级的 `data` 文件夹**，运行文件位于同级的 `runtime`，日志位于 `tray.log`。退出托盘程序会停止服务；「重启」不会清除数据。更新前先从托盘退出，再安装新版或替换便携版 EXE。卸载安装版时会保留 `data`，需要清除歌词库时再自行删除；重新安装到同一目录可继续使用原数据。

如果用过旧版 EXE，请先从托盘退出旧版，再把旧目录 `%LOCALAPPDATA%\Kikoeta-LLS\data` 整个复制到新版 EXE 同级的 `data` 文件夹。确认新版能正常读取原有歌词后，才删除旧目录。若新版同级已存在 `data` 文件夹，请先备份并核对内容，不要直接覆盖。

从源码运行时，安装 **Node.js 24.15.0 或更新版本**，下载并解压本项目源码，然后双击 `start.bat`。首次启动缺少依赖时会自动安装，请保持网络连接。

源码方式运行期间需保持命令窗口开启，按 `Ctrl+C` 停止服务。

### Linux / Docker

下载源码，在项目目录执行：

```sh
docker compose up -d --build
```

打开 `http://服务器地址:2376/login`，使用 `admin / kikoeta-lrc` 登录并设置新密码。

数据保存在 Compose 的 `lls_data` 命名卷中，重建容器后仍会保留。**删除数据卷会丢失歌词和账号配置。**

### 手动启动

安装 Node.js 24.15.0 或更新版本后，在项目目录执行：

```sh
npm ci
npm start
```

## 导入与管理歌词

打开管理页的「歌词库」，按需要选择导入方式。

### 上传歌词文件

1. 在「歌词」模式填写作品号，例如 `RJ123456`，也支持 `VJ`、`BJ` 开头的作品号。
2. 选择一个或多个歌词文件，按需填写子目录，例如 `disc1`。
3. 按需勾选「标记为 AI 歌词」，点击「上传到歌词库」。

上传到同一作品、同一路径的文件会覆盖原文件。单文件最大 **8 MiB**，不能为空；每部作品最多 **256 个文件、合计 32 MiB**。

### 批量导入 ZIP

切换到「压缩包」模式，选择一个或多个 ZIP，再选择同名歌词的处理方式和 AI 标记，点击「批量导入」。

作品号可来自包内的 RJ / VJ / BJ 目录，或压缩包文件名。例如：

```text
RJ123456.zip
└── disc1/track01.lrc

歌词合集.zip
├── RJ123456/track01.lrc
└── VJ654321.zip
    └── track02.srt
```

同名歌词可选择「跳过已有文件」「覆盖已有文件」或「跟随设置」。单个 ZIP 最大 **512 MiB**，累计解压内容上限 **2 GiB**，另有条目数和嵌套深度限制。

导入后，可在作品列表中搜索文件、修改 AI 标记或删除歌词。没有可用歌词文件的作品不会显示在远程库中。

## 连接 Kikoeta

在 Kikoeta 的「导入 → 远程库」中填写：

```text
http://服务器地址:2377
```

如果 Kikoeta 与服务运行在同一台电脑，可使用 `http://127.0.0.1:2377`；手机或其他设备请填写服务器的局域网 IP 或域名，并确保能够访问相应端口。

三个端口的用途不同：

| 默认端口 | 用途 | 在哪里使用 |
| --- | --- | --- |
| `2376` | 网页管理 | 浏览器打开，登录后管理歌词和设置 |
| `2377` | 歌词库只读接口 | Kikoeta 的远程库地址 |
| `2378` | 翻译歌词上传 | Kikoeta Transl 的同步地址 |

## 连接 Kikoeta Transl

1. 在 LLS 的「设置 → Kikoeta Transl 上传」中，设置独立的上传账号密码，或生成／填写 **12 位字母数字密钥**。
2. 在 Kikoeta Transl 的「输出」页开启同步上传，填写对应凭据。
3. Transl 与 LLS 在同一台机器时，地址可留空，默认使用 `http://127.0.0.1:2378`；跨机器时填写 `http://服务器地址:2378`。

同步适用于来自 Kikoeta、带有效作品号且成功完成的任务。上传的歌词会标记为 AI，同一路径的文件会被覆盖。

上传凭据与管理员登录信息独立。账号密码与密钥只能启用一种，保存新方式会停用另一种；未配置时不接受上传。密钥保存后可在设置页再次查看和复制。旧版本仅保存摘要的密钥需要重新设置后才能查看。

## 设置与备份

「设置」页可修改管理员账号和密码；修改后，其他设备需要重新登录。主题、默认 AI 标记和 ZIP 同名文件偏好保存在当前浏览器中。

Windows 单文件版的数据默认位于 EXE 同级的 `data` 文件夹；从源码运行时默认位于项目的 `data` 目录；Docker 中位于数据卷对应的 `/data`：

| 文件 | 内容 |
| --- | --- |
| `library.sqlite` | 歌词原始内容、作品索引与 AI 标记 |
| `admin-credentials.json` | 管理员账号与密码哈希 |
| `transl-credentials.json` | Transl 上传凭据，包含可再次查看的密钥原文 |

**备份前先停止服务，再复制整个数据目录或备份数据卷。** 请妥善保存备份并限制数据目录的访问权限。服务重启后，需要重新登录管理页。

## 部署说明

`2377` 的歌词库接口无需登录，能够访问该端口的设备即可读取歌词。公网部署时，请按需要限制访问范围，并通过 HTTPS 反向代理访问管理页和上传接口。

自定义端口、数据目录、HTTPS 配置和接口格式见 [配置与 API](<docs/配置与 API.md>)。

维护者通过 GitHub Actions 手动构建并上传到 Docker Hub 的步骤见 [Docker 镜像发布](<docs/Docker 镜像发布.md>)。
